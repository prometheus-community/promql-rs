# promql-parser

A standalone PromQL parser ported from upstream `promql/parser` at the
[vendored Prometheus revision](upstream/UPSTREAM.md). It turns query text into
an `Expr` tree that mirrors upstream `ast.go`. The parser does not access
storage or evaluate queries. [promql-engine](../promql-engine/README.md)
consumes the AST.

## Public interface

The crate exposes these entry points and types:

| Item | Upstream | Behavior |
|---|---|---|
| `parse_expr` | `parser.ParseExpr` | Returns `Result<Expr, ParseErrors>`. Experimental syntax is off by default. |
| `parse_metric_selector` | `ParseMetricSelector` | Parses `foo{a="b"}` into `Vec<LabelMatcher>`. A bare metric name becomes a `__name__` matcher. |
| `parse_metric` | `START_METRIC` mode | Parses a bare label set such as `{a="b"}`. |
| `parse_series_desc` | `ParseSeriesDesc` | Parses a promqltest series line such as `x{a="b"} 1+1x10`. Expands value runs at parse time. |
| `Parser::new(ParserOptions)` | `NewParser(Options)` | Provides the same entry points with explicit options. |
| `ParserOptions`, `FEATURE_FLAGS`, `FeatureFlag` | `parser.Options` | Experimental syntax flags. `with_flag` accepts an upstream `--enable-feature` name. `ParserOptions::all()` corresponds to upstream `TestParserOpts`. |
| `ast::*` | `ast.go` | AST nodes, label matchers, and vector-matching types. `Expr` is an enum over the node structs. Fields use upstream names in `snake_case`. |
| `ParseError`, `ParseErrors` | `ParseErr`, `ParseErrors` | Parse errors with byte positions. Parsing continues after an error, as upstream does. |
| `posrange::PositionRange`, `token::Item`, `token::ItemType` | `posrange`, `lex.go` | Byte ranges and token types. AST operators and aggregations use `ItemType`. |
| `functions::is_experimental` | `Functions[…].Experimental` | Reports whether a function requires `enable_experimental_functions`. |
| `parse_duration_seconds` | `model.ParseDuration` | Parses durations such as `5m` and `1h30m` into seconds. |

### Expression example

The aggregate node retains the `by (job)` grouping:

```rust
use promql_parser::{ast::Expr, parse_expr};

let expr = parse_expr(r#"sum by (job) (rate(http_requests_total{code=~"5.."}[5m]))"#)?;
if let Expr::Aggregate(agg) = &expr {
	assert_eq!(agg.grouping, ["job"]);
}
```

### Experimental syntax

`ParserOptions::with_flag` enables a flag by its upstream name:

```rust
use promql_parser::{Parser, ParserOptions};

let options = ParserOptions::default()
	.with_flag("promql-experimental-functions", true)
	.unwrap();
let expr = Parser::new(options).parse_expr("sort_by_label(up, \"job\")")?;
```

The [feature-flag reference](../docs/feature-flags.md) lists the flags and the
syntax each one controls.

### Function types

The parser builds the AST. `promql-engine` checks function arity and argument
types and determines expression return types. The
[engine API](../promql-engine/README.md#query-api) describes query planning and
type inspection.

## Implementation

`grammar.y` preserves upstream non-terminal names, rule order, and precedence.
Its action bodies call Rust helpers in `actions.rs`. Actions record errors in
`ParserCtx` and check experimental syntax flags as they build each construct.

The parser uses one grammar for expressions, metric selectors, bare metrics,
and series descriptions. `InjectingLexer` in `parser.rs` prepends a `START_*`
token to select the grammar entry point. Series descriptions use `series.l`
because spaces and `x` have different meanings in series lines.

The [parser sync design](../docs/parser-sync.md) describes the translation
rules and upstream upgrade procedure.

## Conformance limits

An upstream grammar alternative without a Rust action compiles as an `Err(())`
placeholder and produces a parse error. This command reports unmapped
alternatives and their count without changing `grammar.y`:

```sh
cargo run -p promql-sync -- generate-grammar --dry-run
```

The [open follow-ups](../docs/parser-sync.md#open-follow-ups) describe remaining
parser work. [`grammar-actions.toml`](grammar-actions.toml) records skipped
rules and the Rust actions for supported alternatives.

`tests/conformance.rs` compares parse success or failure against the upstream
`parse_test.go` corpus and enforces a pass-rate floor. The fixture is
`tests/fixtures/parse_test_corpus.json`, generated by `scripts/gen-conformance`.
